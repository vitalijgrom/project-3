# Как развернуть дашборды на Cloudflare Pages

Инструкция рассчитана на то, что вы всё делаете сами и раньше с Cloudflare
Pages не работали. Каждый шаг заканчивается проверкой — если увидели описанное,
идите дальше; если нет, смотрите раздел [Если что-то пошло не так](#если-что-то-пошло-не-так).

Весь путь занимает 15–20 минут, из них большая часть — ожидание выпуска
сертификата.

В примерах поддомен — `uptime.dump.su`. Подставьте свой: имя домена нигде в
коде не зашито, оно задаётся только в интерфейсе Cloudflare.

---

## Что должно быть под рукой

* Аккаунт Cloudflare, в котором **уже добавлен ваш домен**.
  Проверить: [dash.cloudflare.com](https://dash.cloudflare.com) → в левом меню
  **Websites** → домен в списке со статусом **Active**.
* Доступ к репозиторию `vitalijgrom/project-3` на GitHub.
* Google Таблица мониторинга, открытая на чтение по ссылке.
  Проверить: откройте таблицу → **Доступ** (Share) → должно быть
  «Любой, у кого есть ссылка» + роль «Читатель».

Ничего устанавливать на компьютер не нужно — всё делается в браузере.

---

## Шаг 1. Влить изменения в основную ветку

Cloudflare будет собирать ветку `main`, а код пока лежит в отдельной ветке
`claude/dashboards-spreadsheet-dwc3qg`.

1. Открыть репозиторий на GitHub → вкладка **Pull requests**.
2. Открыть пул-реквест с этой веткой и нажать **Merge pull request**, затем
   **Confirm merge**. Если пул-реквеста нет, GitHub предложит его создать
   кнопкой **Compare & pull request** на вкладке **Code**.

**Проверка.** В репозитории на вкладке **Code** в ветке `main` видны папки
`public`, `functions`, `scripts` и файл `wrangler.toml`.

---

## Шаг 2. Создать проект Cloudflare Pages

1. Зайти на [dash.cloudflare.com](https://dash.cloudflare.com).
2. В левом меню выбрать **Workers & Pages**.
3. Нажать **Create application** → перейти на вкладку **Pages** → нажать
   **Connect to Git**.
4. Cloudflare попросит подключить GitHub — нажать **Connect GitHub**.
   Откроется страница GitHub с запросом прав:
   * выбрать **Only select repositories**;
   * в списке отметить **project-3**;
   * нажать **Install & Authorize**.
5. Вернувшись в Cloudflare, выбрать в списке репозиторий **project-3** и нажать
   **Begin setup**.
6. Заполнить форму. Поля, которых нет в таблице, не трогать:

   | Поле | Что вписать |
   |---|---|
   | Project name | `uptime-monitoring-dashboard` |
   | Production branch | `main` |
   | Framework preset | `None` |
   | Build command | **оставить пустым** |
   | Build output directory | `public` |
   | Root directory (advanced) | не трогать |
   | Environment variables | не трогать, см. Шаг 3 |

7. Нажать **Save and Deploy**.

Сборки как таковой нет — Cloudflare просто раскладывает содержимое папки
`public`. Обычно это 20–40 секунд.

**Проверка.** Появился экран **Success! Your project is deployed to
`uptime-monitoring-dashboard.pages.dev`**.

> Имя проекта задаёт адрес технической выдачи. Если `uptime-monitoring-dashboard`
> занят, Cloudflare предложит другое — запомните его, дальше оно понадобится.

---

## Шаг 3. Переменные окружения — ничего делать не нужно

Настройки таблицы (`SHEET_ID`, `CACHE_TTL`) лежат в файле `wrangler.toml` в
репозитории. Для Cloudflare Pages этот файл — источник истины: в разделе
**Settings → Variables and Secrets** вы эти переменные увидите, но поля будут
недоступны для редактирования. Так и задумано.

Менять данные нужно **в файле** `wrangler.toml`, а не в интерфейсе: правите,
коммитите — Cloudflare пересоберёт проект сам.

<details>
<summary>Если хочется управлять переменными из интерфейса Cloudflare</summary>

Удалите из `wrangler.toml` блок `[vars]` целиком, запушьте изменение, а затем
в **Settings → Variables and Secrets** добавьте две переменные —
отдельно для окружения **Production** и **Preview**:

| Переменная | Значение |
|---|---|
| `SHEET_ID` | `1QgzU7AnrH6Cu-KWdeio2u4kJadfqhfQJZ04iOM3uMWE` |
| `CACHE_TTL` | `300` |

Так же поступите, если считаете ID таблицы чувствительным: в интерфейсе его
можно завести как **Secret**, и в репозитории он тогда не хранится.
</details>

## Шаг 4. Убедиться, что всё работает на технической выдаче

Прежде чем цеплять свой домен, проверьте проект на адресе `*.pages.dev`.

1. Открыть в браузере `https://uptime-monitoring-dashboard.pages.dev`.
2. Дашборд должен показать данные: **36 сайтов и 19 почтовых узлов**,
   доступность около **83%** (цифры меняются вместе с таблицей).

**Проверка.**

* Вверху **нет жёлтой полосы** с текстом про снапшот.
* Внизу страницы написано **«Источник: Google Таблица»**.

Если жёлтая полоса есть — прослойка не поднялась, откройте
`https://uptime-monitoring-dashboard.pages.dev/api/monitor` напрямую и
посмотрите текст ошибки, дальше по таблице диагностики.

> Первый запрос после деплоя идёт дольше остальных: прослойка делает девять
> запросов к Google и складывает ответ в edge-кэш. Дальше страница открывается
> мгновенно, пока кэш не истечёт.

## Шаг 5. Создать поддомен

**Важно: не создавайте DNS-запись вручную.** Cloudflare создаст её сам, и это
единственный правильный порядок. Если запись появится в DNS раньше, чем домен
привязан к проекту, поддомен будет отдавать ошибку **522**.

1. Открыть свой проект: **Workers & Pages** → **uptime-monitoring-dashboard**.
2. Перейти на вкладку **Custom domains**.
3. Нажать **Set up a domain**.
4. В поле ввести полностью: `uptime.dump.su`
5. Нажать **Continue**.
6. Cloudflare покажет запись, которую собирается создать:

   | Type | Name | Content |
   |---|---|---|
   | CNAME | `uptime` | `uptime-monitoring-dashboard.pages.dev` |

7. Нажать **Activate domain**.

Статус домена будет меняться: **Initializing** → **Pending** → **Active**.
Обычно это 1–3 минуты, изредка до 15 — Cloudflare в это время выпускает
SSL-сертификат. Страницу можно обновлять.

**Проверка.** В списке **Custom domains** напротив вашего поддомена стоит
статус **Active**.

Заодно можно убедиться, что запись создалась: **Websites** → ваш домен →
**DNS** → **Records**. Там появилась строка `CNAME` с оранжевым облачком
(**Proxied**). Облачко трогать не нужно — оно должно остаться оранжевым.

## Шаг 6. Финальная проверка

Открыть `https://uptime.dump.su`.

Должно быть:

* замок в адресной строке (сертификат выпущен);
* данные на месте, жёлтой полосы нет;
* внизу «Источник: Google Таблица».

Нажмите кнопку **Обновить** в правом верхнем углу — цифры перечитаются из
таблицы напрямую, минуя кэш.

На этом дашборды развёрнуты.

## Шаг 7. Закрыть дашборд от посторонних (рекомендуется)

Сейчас страница доступна любому, кто знает адрес. В разметке стоит
`noindex, nofollow`, поэтому в поиске она не появится, но от прямой ссылки это
не защищает.

Так как домен уже проксируется через Cloudflare, закрыть его можно штатно, без
туннелей и агентов:

1. В левом меню дашборда выбрать **Zero Trust**.
   При первом входе Cloudflare попросит выбрать план — free-тарифа хватает.
2. **Access controls** → **Applications** → **Create new application**.
3. Выбрать тип **Self-hosted and private**, затем **Add public hostname**.
4. Заполнить:
   * **Application name** — `Uptime dashboards`
   * **Domain** — выбрать свой домен, в поле поддомена вписать `uptime`
   * **Path** — оставить пустым, чтобы закрыть весь дашборд
5. На шаге политик добавить правило:
   * **Policy name** — `Разрешённые сотрудники`
   * **Action** — **Allow**
   * **Include** — `Emails` и перечислить адреса, либо
     `Emails ending in` и указать домен вашей почты
6. Сохранить: **Create**.

**Проверка.** Откройте `https://uptime.dump.su` в режиме инкогнито —
Cloudflare попросит ввести почту и одноразовый код.

Прослойка `/api/monitor` закроется вместе со страницей — так и нужно: дашборд
обращается к ней из уже авторизованного браузера, отдельной настройки не
требуется.

## Как обновлять дальше

* **Данные.** Мониторинг сам пишет в Google Таблицу — дашборд подхватит
  изменения максимум через `CACHE_TTL` секунд (сейчас 5 минут). Кнопка
  **Обновить** делает это мгновенно.
* **Код и настройки.** Любой коммит в ветку `main` запускает новый деплой
  автоматически, руками ничего нажимать не нужно.
* **Снапшот.** Файл `public/data/fallback.json` показывается, только если
  прослойка недоступна. Обновить его: `npm run snapshot`, затем закоммитить.
* **Откат.** Проект → **Deployments** → у нужного деплоя `···` → **Rollback to
  this deployment**.
* **Посмотреть логи функции.** Проект → **Functions** (или **Logs**) →
  **Begin log stream**, затем обновить страницу дашборда.

## Если что-то пошло не так

| Что видите | Из-за чего | Что делать |
|---|---|---|
| Поддомен отдаёт **522** | CNAME создали вручную до привязки домена к проекту | **Websites → домен → DNS → Records**, удалить запись, затем пройти Шаг 5 заново |
| Поддомен «висит» в **Pending** дольше 15 минут | домен в другом аккаунте Cloudflare, не в том, где проект | Мастер привязки покажет TXT-запись для подтверждения — добавьте её в DNS зоны |
| Жёлтая полоса «Показан локальный снапшот» | прослойка `/api/monitor` не отвечает | Открыть `/api/monitor` напрямую и смотреть текст ошибки — строки ниже |
| `/api/monitor` отдаёт **404** | в Build output directory указано не `public` | **Settings → Builds** → исправить на `public` → **Retry deployment** |
| **502** и текст `Google Sheets ответил 404` | неверный `SHEET_ID` | Сверить ID со ссылкой на таблицу: он между `/d/` и `/edit` |
| **502** и текст `gviz вернул ошибку` | у таблицы закрыт доступ по ссылке | Таблица → **Доступ** → «Любой, у кого есть ссылка», роль «Читатель» |
| **502** и в тексте ошибки имя листа | лист переименован или удалён | Сверить имена листов с таблицей в README, поправить `SCOPES` в `functions/api/monitor.js` |
| Вкладка есть, но карточки пустые | в журнале нет событий с ожидаемыми именами | Сверить названия событий в листе логов с `okEvent` / `failEvent` в `SCOPES` |
| Правки в таблице не видны | ответ лежит в кэше | Нажать **Обновить** на дашборде или подождать `CACHE_TTL` |
| В подвале `edge-кэш: STALE` | Google Таблицы временно недоступны, показан последний удачный ответ | Ничего не делать, пройдёт само |

## Приложение: деплой без подключения к GitHub

Разовая загрузка с компьютера, если по каким-то причинам не хотите связывать
Cloudflare с репозиторием. Нужен установленный Node.js.

```bash
git clone https://github.com/vitalijgrom/project-3.git
cd project-3
npm install
npx wrangler pages project create uptime-monitoring-dashboard
npx wrangler pages deploy public
```

Поддомен подключается так же — Шаг 5 через интерфейс.

Учтите: проект, созданный прямой загрузкой (Direct Upload), **нельзя** потом
подключить к Git — придётся удалять и создавать заново. Если планируете
автодеплой из репозитория, идите по Шагу 2.
